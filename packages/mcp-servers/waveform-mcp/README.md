# waveform-mcp

MCP server for simulation waveform (VCD / FST) parsing, compression, and
LLM-backed anomaly debug.

## Overview

Parses VCD (natively via ``vcdvcd``) and FST (via GTKWave's ``fst2vcd``)
waveform dumps and exposes them to Claude Code / Codex CLI / OpenCode via
the MCP protocol. Five parsing/compression tools handle size reduction and
protocol decoding; one LLM-backed skill absorbs the ``waveform_debug``
pipeline from the retired ``packages/skills/`` monolith.

| Skill | Tool | Model default | What it does |
| --- | --- | --- | --- |
| waveform_debug | `debug_waveform` | `claude` | 5 detectors (glitch / X-Z / CDC / AXI / stall) + LLM root-cause + fix |

The detectors are pure-Python and deterministic — they run in-process, fully
offline. The LLM reasoning pass goes through the shared
[`vibe4fpga-llm-client`](../../shared/llm-client/) adapter library, so any
backend key from its registry (`claude`, `gpt-4o`, `deepseek`, `gemini`,
`ollama`, `rtlcoder`, …) works without code changes.

An internal LRU cache keeps the last 8 parsed waveforms hot, so repeated
tool calls against the same VCD reuse the same `WaveformMetadata`.

## Install

```bash
uv tool install waveform-mcp                      # PATH entry "waveform-mcp"
```

Developers working inside the monorepo use path-deps instead:

```bash
cd packages/mcp-servers/waveform-mcp
uv sync --all-extras
```

FST support is optional — install GTKWave on the host if you need it
(``brew install gtkwave`` / Windows installer). VCD needs nothing beyond
this package.

## Configure

### Claude Code — `%USERPROFILE%\.claude.json`

```json
{
  "mcpServers": {
    "waveform": {
      "command": "waveform-mcp",
      "env": { "ANTHROPIC_API_KEY": "${env:ANTHROPIC_API_KEY}" }
    }
  }
}
```

### Codex CLI — `%USERPROFILE%\.codex\config.toml`

```toml
[mcp_servers.waveform]
command = "waveform-mcp"
```

### OpenCode — `%APPDATA%\opencode\config.json`

```json
{ "mcp": { "waveform": { "type": "stdio", "command": ["waveform-mcp"] } } }
```

Host snippets are regenerated by `tools/gen-skills/generate.py` — never
hand-edit the files under `configs/`.

## Tools

### Parsing + compression (no LLM)

| Tool | Purpose |
| --- | --- |
| `parse_waveform_tool` | Read a VCD/FST and return metadata (duration, clocks, signal list) |
| `extract_signal_events` | L1-compressed `{time, value}` events for a signal whitelist, optional time window |
| `decode_axi_tool` | AXI4 5-channel state machine decode + violation list |
| `summarize_for_llm` | Full three-level compression → token-bounded narrative for LLM context |
| `map_signal_to_rtl` | Reverse-map a simulation hierarchy signal to RTL source lines |

### LLM-backed

| Tool | Input model | Notes |
| --- | --- | --- |
| `debug_waveform` | `DebugWaveformInput` | Runs 5 detectors in parallel then asks the LLM for root cause + RTL fix |

## Environment

| Var | Required for | Default |
| --- | --- | --- |
| `VIBE4FPGA_LLM` | picking default backend for `debug_waveform` | `claude` |
| `ANTHROPIC_API_KEY` | `VIBE4FPGA_LLM=claude` (default) | — |
| `OPENAI_API_KEY` | OpenAI / DeepSeek backends | — |
| `GEMINI_API_KEY` or `GOOGLE_API_KEY` | Gemini backend | — |
| `OLLAMA_BASE_URL` | Ollama / RTLCoder | `http://localhost:11434` |

See [`vibe4fpga-llm-client` README](../../shared/llm-client/README.md) for the
full backend table. The five parsing tools require no environment
variables.

## Windows notes

* **No `/tmp`.** The parser's optional ``fst2vcd`` conversion writes to an
  OS-appropriate temp directory (``%TEMP%`` on Windows). The LLM-backed
  skill never touches disk outside the input waveform path.
* **FST prerequisite.** Install GTKWave so ``fst2vcd.exe`` is on PATH; the
  parser uses ``shutil.which`` to locate it and returns a clear error when
  absent.
* **Long VCDs.** Large simulator dumps (> 1 GB) should be pre-trimmed with
  a simulator-side time window — `vcdvcd` loads the full file into memory.
  The LRU cache keeps at most 8 waveforms resident.
* **UTF-8 console.** If you invoke the MCP via a host that bypasses a
  ``vibe4fpga-platform`` launcher, export ``PYTHONIOENCODING=utf-8``
  manually so non-ASCII signal scopes decode cleanly.

## Troubleshooting

* `AuthError: ANTHROPIC_API_KEY is not set` — `VIBE4FPGA_LLM=claude`
  requires the key. Set it in the host config or switch `VIBE4FPGA_LLM` to
  `ollama` for offline operation.
* `fst2vcd not found` — install GTKWave; the package parses VCD natively
  so this only affects `.fst` files.
* `Failed to parse waveform: list index out of range` — the dump is
  truncated or the simulator wrote an unsupported VCD dialect. Re-dump
  with ``$dumpall`` enabled or convert to VCD via ``vcd2vcd``.
* `debug_waveform` returns an empty `llm_analysis` but non-zero
  `anomaly_count` — the detectors fired, but the LLM declined to comment.
  Check the `model` parameter and API key, or lower `temperature` by
  editing ``skills/waveform_debug/skill.py``.
* `CDCDetector` reports false positives on deeply-pipelined single-clock
  designs — the detector relies on transition-vs-clock-edge proximity and
  cannot replace a structural CDC analyzer. Cross-check with
  `eda-bridge-mcp`'s lint path.
