# yosys-mcp

MCP server bridging the open-source FPGA toolchain — Yosys for synthesis,
nextpnr for place & route, and Icestorm (`icepack`) for iCE40 bitstream
packing. Supports iCE40 and ECP5 targets and exposes a Yosys-based formal
verification prep tool (SMT2 output) for SymbiYosys.

## Overview

This MCP is a thin, tool-discovery-aware wrapper: every invocation routes
through [`vibe4fpga-platform`](../../shared/platform/) so binary lookup,
subprocess spawning, UTF-8 encoding, long-path handling, and timeout drain
behave identically on macOS and Windows.

| Tool | Backing binary | What it does |
| --- | --- | --- |
| `synthesize_ice40` | `yosys` → `synth_ice40` | HDL → iCE40-specific JSON netlist |
| `synthesize_ecp5`  | `yosys` → `synth_ecp5`  | HDL → ECP5-specific JSON netlist |
| `synthesize_generic` | `yosys` → `synth`     | Technology-independent JSON netlist |
| `prepare_formal_verification` | `yosys` → `write_smt2` | SV with SVA → SMT2 for SymbiYosys |
| `pnr_ice40` | `nextpnr-ice40` | PnR with optional `.pcf` pin map + fmax constraint |
| `pnr_ecp5`  | `nextpnr-ecp5`  | PnR with optional `.lpf` pin map + fmax constraint |
| `pack_ice40_bitstream` | `icepack` | `.asc` → `.bin` bitstream |

No LLM calls are made — `skill.yaml` declares zero skills, so no
`ANTHROPIC_API_KEY` / `OPENAI_API_KEY` is required.

## Install

The MCP itself:

```bash
uv tool install yosys-mcp                 # installs PATH entry "yosys-mcp"
```

Toolchain binaries — `yosys-mcp` shells out to these, so they must be
reachable (either on PATH or via the `*_PATH` env vars below):

* **macOS** — `brew install yosys nextpnr icestorm`
* **Windows** — the easiest route is the
  [YosysHQ oss-cad-suite](https://github.com/YosysHQ/oss-cad-suite-build)
  zip bundle (contains yosys, nextpnr-*, icestorm). Alternatively use
  Scoop: `scoop bucket add extras && scoop install yosys`.

Developers working inside the monorepo use path-deps instead:

```bash
cd packages/mcp-servers/yosys-mcp
uv sync --all-extras
```

## Configure

### Claude Code — `~/.claude.json` / `%USERPROFILE%\.claude.json`

```json
{
  "mcpServers": {
    "yosys": {
      "command": "yosys-mcp"
    }
  }
}
```

### Codex CLI — `%USERPROFILE%\.codex\config.toml`

```toml
[mcp_servers.yosys]
command = "yosys-mcp"
```

### OpenCode — `%APPDATA%\opencode\config.json`

```json
{ "mcp": { "yosys": { "type": "stdio", "command": ["yosys-mcp"] } } }
```

Host snippets are regenerated by `tools/gen-skills/generate.py` — never
hand-edit the files under `configs/`.

## Tools

All tools are async and return structured `dict` payloads with `success`,
`errors`, `warnings`, and tool-specific fields (e.g. `cells`, `fmax_mhz`,
`utilization`, `output_json`, `output_asc`, `output_bin`). See docstrings
in `src/yosys_mcp/server.py` for the full schema.

Typical flow for iCE40:

1. `synthesize_ice40(source_files, top_module)` → returns `output_json`.
2. `pnr_ice40(netlist_json, pcf_file="pins.pcf", device="hx8k")` → returns `output_asc`.
3. `pack_ice40_bitstream(asc_file)` → returns `output_bin`.

For ECP5 swap steps 1 & 2 for the `_ecp5` variants and use `.lpf` instead
of `.pcf`. For formal flows call `prepare_formal_verification` and feed
the resulting `.smt2` to SymbiYosys.

## Environment

| Var | Purpose | Default |
| --- | --- | --- |
| `YOSYS_PATH`          | Override `yosys` binary lookup        | PATH |
| `NEXTPNR_ICE40_PATH`  | Override `nextpnr-ice40` binary       | PATH |
| `NEXTPNR_ECP5_PATH`   | Override `nextpnr-ecp5` binary        | PATH |
| `ICEPACK_PATH`        | Override `icepack` binary             | PATH |

When none of these is set, `vibe4fpga-platform.find_tool` falls back to
`shutil.which` (which honours `PATHEXT` on Windows), and also retries with
`.exe` suffix as a belt-and-brace.

## Windows notes

* **No `/tmp`.** Scratch paths go through
  [`vibe4fpga-platform.scratch_dir`](../../shared/platform/) which registers
  the directory for atexit cleanup and survives `long_path` prefixing.
* **Long paths.** The platform layer transparently prefixes `\\?\` on paths
  exceeding 240 chars; still advisable to enable `LongPathsEnabled=1` in
  Windows group policy for deep synthesis project trees.
* **UTF-8 console.** `PYTHONUTF8=1` is set in child env by
  `platform.proc.run`, keeping yosys stdout readable on CN Windows.
* **oss-cad-suite activation.** If you use the YosysHQ bundle, run its
  `environment.bat` (or `environment.sh` on macOS) once per shell, or point
  the four `*_PATH` env vars directly at `<install>/bin/`.

## Troubleshooting

* *"yosys not found"* — install via Homebrew / oss-cad-suite, or set
  `YOSYS_PATH` to an absolute path.
* *"nextpnr-ice40 not found"* — same as above; note that nextpnr comes as
  one binary per family (`nextpnr-ice40`, `nextpnr-ecp5`).
* *Empty `cells` fields in synthesis result* — the parser is stat-line
  based; run with `extra_flags="-noflatten"` disabled or inspect
  `log_excerpt` for the raw Yosys report.
* *PnR silently reports `fmax_mhz: None`* — nextpnr only prints an fmax
  line when a `freq_constraint_mhz` is supplied.
* *Process times out* — bump the `timeout` kwarg on the corresponding
  tool call (default 120 s for synth, 300 s for PnR, 30 s for icepack).
