# fpga-project-mcp

MCP server for FPGA project indexing with three LLM-backed design skills.

## Overview

Scans a Verilog/SystemVerilog tree to build a module dependency graph and
exposes it to Claude Code / Codex CLI / OpenCode via the MCP protocol. Also
hosts three LLM-backed skills absorbed from the retired `packages/skills/`
monolith:

| Skill | Tool | Model default | What it does |
| --- | --- | --- | --- |
| spec2rtl   | `spec_to_rtl`        | `claude` | 5-stage NL-spec → synthesizable Verilog pipeline |
| code_review| `review_rtl`         | `claude` | 10-item FPGA-pitfall checker (latch, CDC, reset, ...) |
| timing_fix | `suggest_timing_fix` | `claude` | Vivado timing report → per-path fixes |

LLM calls go through the shared [`vibe4fpga-llm-client`](../../shared/llm-client/)
adapter library, so any backend key from its registry (`claude`, `gpt-4o`,
`deepseek`, `gemini`, `ollama`, `rtlcoder`, ...) works without code changes.

## Install

```bash
uv tool install fpga-project-mcp                 # PATH entry "fpga-project-mcp"
# With optional vector-search (sentence-transformers is ~300 MB):
uv tool install 'fpga-project-mcp[embed]'
```

Developers working inside the monorepo use path-deps instead:

```bash
cd packages/mcp-servers/fpga-project-mcp
uv sync --all-extras
```

## Configure

### Claude Code — `%USERPROFILE%\.claude.json`

```json
{
  "mcpServers": {
    "fpga-project": {
      "command": "fpga-project-mcp",
      "env": { "ANTHROPIC_API_KEY": "${env:ANTHROPIC_API_KEY}" }
    }
  }
}
```

### Codex CLI — `%USERPROFILE%\.codex\config.toml`

```toml
[mcp_servers.fpga-project]
command = "fpga-project-mcp"
```

### OpenCode — `%APPDATA%\opencode\config.json`

```json
{ "mcp": { "fpga-project": { "type": "stdio", "command": ["fpga-project-mcp"] } } }
```

Host snippets are regenerated by `tools/gen-skills/generate.py` — never
hand-edit the files under `configs/`.

## Tools

### Static (no LLM)

| Tool | Purpose |
| --- | --- |
| `scan_project` | File tree + module dependency graph |
| `get_hierarchy` | Top-down nested tree |
| `search_signal_tool` | Cross-file grep for signal refs |
| `analyze_naming_conventions_tool` | Statistical convention scoring (>0.70 only) |
| `get_interface_neighbors` | Parent / child modules of a given module |
| `find_similar_modules` | Keyword-match shortlist (vector search coming in v0.3) |

### LLM-backed

| Tool | Input model | Notes |
| --- | --- | --- |
| `spec_to_rtl` | `SpecToRtlInput` | Accepts optional `project_path` for in-process naming-convention injection |
| `review_rtl` | `ReviewRtlInput` | Takes `rtl_code` string; pair with `scan_project` to review a whole file tree |
| `suggest_timing_fix` | `SuggestTimingFixInput` | Auto-extracts WNS/TNS when omitted |

## Environment

| Var | Required for | Default |
| --- | --- | --- |
| `VIBE4FPGA_LLM` | picking default backend | `claude` |
| `ANTHROPIC_API_KEY` | `VIBE4FPGA_LLM=claude` (default) | — |
| `OPENAI_API_KEY` | OpenAI / DeepSeek backends | — |
| `GEMINI_API_KEY` or `GOOGLE_API_KEY` | Gemini backend | — |
| `OLLAMA_BASE_URL` | Ollama / RTLCoder | `http://localhost:11434` |

See [`vibe4fpga-llm-client` README](../../shared/llm-client/README.md) for the
full backend table.

## Windows notes

* **No `/tmp`.** Subprocess + scratch paths go through
  [`vibe4fpga-platform`](../../shared/platform/). If you ever need a scratch
  file from tool code, use `from vibe4fpga_platform import scratch_file`.
* **Long paths.** `vibe4fpga-platform` transparently prefixes `\\?\` on paths
  exceeding 240 chars; enable `LongPathsEnabled=1` in Windows group policy
  for Vivado build dirs regardless.
* **UTF-8 console.** `PYTHONUTF8=1` is set in the child env by
  `platform.proc.run`. If you invoke the MCP via a host that bypasses our
  wrapper, export `PYTHONIOENCODING=utf-8` manually.

## Troubleshooting

* `AuthError: ANTHROPIC_API_KEY is not set` — `VIBE4FPGA_LLM=claude` requires
  the key. Set it in the host config or switch `VIBE4FPGA_LLM` to `ollama`
  for offline operation.
* `MissingDependencyError: Backend 'gemini' requires optional dependency` —
  install the extra: `uv tool install 'vibe4fpga-llm-client[gemini]'`.
* Tool returns empty `findings` list — the model declined to identify
  issues; lower `temperature` in the skill source or retry with a different
  `model` key.
* Import error `sentence_transformers` — `find_similar_modules` vector path
  is gated behind the `[embed]` extra; falls back to keyword match when
  unavailable.
