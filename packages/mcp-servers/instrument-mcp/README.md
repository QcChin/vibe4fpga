# instrument-mcp

MCP server for oscilloscope / spectrum-analyzer access with a sim-vs-real
waveform diff classifier skill.

## Overview

Wraps the VISA / SCPI ecosystem behind the MCP protocol so Claude Code /
Codex CLI / OpenCode can read oscilloscope CSV exports, capture live
waveforms from networked or USB instruments, align the capture against a
Verilog simulation's VCD trace, and classify any differences into 7
canonical categories. One LLM-backed skill tool (``analyze_instrument_diff``)
then attributes each suspicious / anomalous finding to a root cause
(RTL bug, constraint error, PCB issue, or physical effect).

| Skill | Tool | Model default | What it does |
| --- | --- | --- | --- |
| instrument_analyze | `analyze_instrument_diff` | `claude` | Classify + root-cause oscilloscope vs. simulation diffs |

The classifier itself is pure numpy / scipy — it runs offline, returns
structured results, and is covered by synthetic-array unit tests
(`tests/test_classifier.py`). The LLM layer is *only* used for the
final attribution step, via the shared
[`vibe4fpga-llm-client`](../../shared/llm-client/) registry so any
backend key (`claude`, `gpt-4o`, `deepseek`, `gemini`, `ollama`, ...) works
without code changes.

## Install

```bash
uv tool install instrument-mcp                   # PATH entry "instrument-mcp"
```

Inside the monorepo, use path-deps for editable development:

```bash
cd packages/mcp-servers/instrument-mcp
uv sync --all-extras
```

`pyvisa` is a required dependency so the SCPI tools import cleanly, but
the **VISA backend itself** is platform-specific — see the Windows notes
below.

## Configure

### Claude Code — `%USERPROFILE%\.claude.json`

```json
{
  "mcpServers": {
    "instrument": {
      "command": "instrument-mcp",
      "env": { "ANTHROPIC_API_KEY": "${env:ANTHROPIC_API_KEY}" }
    }
  }
}
```

### Codex CLI — `%USERPROFILE%\.codex\config.toml`

```toml
[mcp_servers.instrument]
command = "instrument-mcp"
```

### OpenCode — `%APPDATA%\opencode\config.json`

```json
{ "mcp": { "instrument": { "type": "stdio", "command": ["instrument-mcp"] } } }
```

Host snippets are regenerated by `tools/gen-skills/generate.py` — never
hand-edit the files under `build/`.

## Tools

### Measurement I/O (no LLM)

| Tool | Purpose |
| --- | --- |
| `read_csv_waveform` | Parse oscilloscope CSV export (Rigol / generic auto-detect) |
| `compute_fft_tool` | Spectral analysis of a CSV waveform (dominant freq + THD) |
| `list_visa_instruments` | Enumerate VISA-accessible instruments |
| `connect_instrument` | Open a VISA connection and issue `*IDN?` |
| `capture_live_waveform` | Live SCPI capture (`:WAV:DATA?` + Tektronix CSV fallback) |
| `align_with_simulation` | Cross-correlate sim (VCD) vs. measurement |
| `classify_differences_tool` | 7-category diff classifier (pure numpy) |

### LLM-backed

| Tool | Input model | Notes |
| --- | --- | --- |
| `analyze_instrument_diff` | `AnalyzeInstrumentDiffInput` | Accepts raw `list[float]` arrays, CSV/VCD paths, or a VISA resource string. Runs align → classify → LLM attribution end-to-end. |

## Windows notes

* **VISA driver install (required for SCPI tools).** `pyvisa` is only a
  *binding* — it still needs a real VISA backend. The two supported
  vendors on Windows are:
    * **NI-VISA** — https://www.ni.com/visa (free, administrator install).
      Covers the vast majority of USB / LAN instruments including
      Rigol, Tektronix, and SIGLENT.
    * **Keysight VISA (IO Libraries Suite)** — https://www.keysight.com/find/iosuite.
      Recommended for Keysight scopes; coexists with NI-VISA.
    * **`pyvisa-py`** (pure Python fallback) — `pip install pyvisa-py pyusb libusb1`.
      No admin rights, but USB enumeration on Windows is best-effort.

  If **no backend is available**, `list_visa_instruments` returns an empty
  list (no exception) so host agents can still call it safely — but
  `connect_instrument` and `capture_live_waveform` will surface a
  structured `RuntimeError` from `_require_pyvisa` with the driver-install
  URLs above. This is deliberate, per risk R3 in the refactor plan: we
  never silently swallow a missing-driver error.

* **No `/tmp`.** Subprocess + scratch paths go through
  [`vibe4fpga-platform`](../../shared/platform/). The Tektronix
  `SAV:WAV ...,CSV` fallback writes into a `vibe4fpga_*` scratch dir that
  is cleaned on interpreter exit. If you ever need a scratch file from
  tool code yourself, use `from vibe4fpga_platform import scratch_file`.
* **Long paths.** `vibe4fpga-platform` transparently prefixes `\\?\` on
  paths exceeding 240 chars; enable `LongPathsEnabled=1` in Windows group
  policy for long capture-archive paths.
* **UTF-8 console.** Instrument replies may include extended characters
  in their `*IDN?` string (e.g. SIGLENT Chinese locale builds). Ensure
  `PYTHONIOENCODING=utf-8` / `chcp 65001` before invoking the MCP
  manually; host wrappers set this for you.

## Troubleshooting

* `RuntimeError: pyvisa backend not available` — install NI-VISA,
  Keysight VISA, or `pip install pyvisa-py pyusb libusb1`. Mac
  developers without physical instruments can continue to use
  `read_csv_waveform`, `align_with_simulation`, `classify_differences_tool`,
  and the array-mode `analyze_instrument_diff` — none of those import
  pyvisa.
* `list_visa_instruments` returns `[]` — either no instruments are
  connected, or the VISA backend is installed but the driver service
  isn't running. On Windows, check `Services → NI-VISA Server` or the
  Keysight Connection Expert.
* `waveform_mcp not available — run waveform-mcp as a sidecar` — the
  VCD parser lives in the waveform-mcp package. Install it with
  `uv tool install waveform-mcp`; the two MCP servers are intentionally
  split so you can run one without the other.
* `AuthError: ANTHROPIC_API_KEY is not set` — `VIBE4FPGA_LLM=claude`
  requires the key. Set it in the host config or switch `VIBE4FPGA_LLM`
  to `ollama` for offline operation.
* `analyze_instrument_diff` returns `{"raw": "..."}` under `llm_analysis`
  — the model response was not valid JSON. Lower `temperature` in the
  skill source or retry with a different `model` key.
