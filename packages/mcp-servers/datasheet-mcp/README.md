# datasheet-mcp

MCP server providing RAG (retrieval-augmented generation) over FPGA
datasheets, protocol specifications, HDL design patterns, and IP-core
interface documents. Backed by a local Qdrant vector store and OpenAI
embeddings (``text-embedding-3-small`` by default).

## Overview

datasheet-mcp is the **knowledge-base** MCP in the vibe4fpga stack. Unlike
the other nine MCPs, it does **not** consume
[`vibe4fpga-llm-client`](../../shared/llm-client/) because that library's
surface is chat completions — datasheet-mcp only calls embedding APIs. The
OpenAI SDK is used directly for embeddings; if/when llm-client grows an
embeddings abstraction, this MCP will be migrated.

Six retrieval tools are exposed:

| Tool | Purpose |
| --- | --- |
| `search_datasheet`      | Semantic search scoped to device datasheets |
| `search_protocol`       | Search protocol specs (AXI, PCIe, DDR, Ethernet, ...) |
| `search_design_pattern` | HDL patterns (CDC synchronizer, handshake, gray code, FIFO) |
| `get_ip_interface`      | IP-core ports / parameters lookup |
| `index_document_tool`   | Incremental re-index of a PDF / text / Markdown file |
| `search_all`            | Unscoped semantic search across the entire store |

Indexing is incremental: each file's SHA-256 is cached, so re-running
`index_document_tool` on an unchanged file is a no-op.

## Install

```bash
uv tool install datasheet-mcp                         # PATH entry "datasheet-mcp"
# Optional offline embeddings (pulls sentence-transformers + torch, ~300 MB):
uv tool install 'datasheet-mcp[offline]'
```

Developers working inside the monorepo use path-deps:

```bash
cd packages/mcp-servers/datasheet-mcp
uv sync --all-extras
```

## Configure

### Claude Code — `%USERPROFILE%\.claude.json`

```json
{
  "mcpServers": {
    "datasheet": {
      "command": "datasheet-mcp",
      "env": { "OPENAI_API_KEY": "${env:OPENAI_API_KEY}" }
    }
  }
}
```

### Codex CLI — `%USERPROFILE%\.codex\config.toml`

```toml
[mcp_servers.datasheet]
command = "datasheet-mcp"
env = { OPENAI_API_KEY = "sk-..." }
```

### OpenCode — `%APPDATA%\opencode\config.json`

```json
{
  "mcp": {
    "datasheet": {
      "type": "stdio",
      "command": ["datasheet-mcp"],
      "env": { "OPENAI_API_KEY": "sk-..." }
    }
  }
}
```

Host snippets are regenerated by `tools/gen-skills/generate.py` — never
hand-edit generated config files.

## Tools

| Tool | Arguments | Notes |
| --- | --- | --- |
| `search_datasheet(query, top_k=5)` | `query: str`, `top_k: int` | Filters to `doc_type=datasheet` |
| `search_protocol(query, protocol=None, top_k=5)` | | Optional protocol token gets prepended to the query |
| `search_design_pattern(query, top_k=3)` | | `doc_type=design_pattern` |
| `get_ip_interface(ip_name, version=None)` | | Auto-crafts a "ports parameters" query |
| `index_document_tool(file_path, doc_type="datasheet")` | | Skips unchanged files via SHA-256 cache |
| `search_all(query, top_k=8)` | | No `doc_type` filter |

All retrieval tools return `list[dict]` with keys
`{source, page, score, text, doc_type}`; on failure each returns a
single-item list `[{"error": "..."}]` so the host never sees a raised
exception mid-stream.

## Environment

| Var | Required for | Default |
| --- | --- | --- |
| `OPENAI_API_KEY`                | Online embeddings (default path) | — |
| `VIBE4FPGA_DATASHEET_DB_PATH`   | Qdrant persistence location override | `~/.vibe4fpga/datasheet_qdrant` |

When `OPENAI_API_KEY` is absent, the indexer falls back to a local
HuggingFace model (`BAAI/bge-small-en-v1.5`) — this only works if the
package was installed with the `[offline]` extra; otherwise a clear
`RuntimeError` is raised telling the user which extra to install.

## Windows notes

* **Qdrant store location.** The default store is
  `%USERPROFILE%\.vibe4fpga\datasheet_qdrant`. Set
  `VIBE4FPGA_DATASHEET_DB_PATH` to a custom absolute path if you want the
  store to live on a different drive or move between machines (external SSD,
  project root, etc.). The legacy `./qdrant_storage` relative path has been
  removed — it resolved unpredictably depending on which directory the MCP
  host happened to launch the server from.
* **Long paths.** Qdrant writes many small files under the store root;
  enable `LongPathsEnabled=1` in Windows group policy before pointing the
  store at a deeply nested directory.
* **UTF-8 console.** PDFs frequently contain non-ASCII glyphs that trip up
  the default CN Windows GBK console. Export `PYTHONIOENCODING=utf-8` (or
  `chcp 65001`) if raw `datasheet-mcp` stdio output looks mojibake'd — the
  MCP itself is always UTF-8 over the MCP protocol.

## Troubleshooting

* **`RuntimeError: No embedding model available`** — Set `OPENAI_API_KEY`
  or install the offline extra: `uv tool install 'datasheet-mcp[offline]'`.
* **`search_*` returns `[{"error": "..."}]`** — The Qdrant store is empty
  or the collection hasn't been created yet. Run
  `index_document_tool(file_path=..., doc_type=...)` at least once first.
* **`index_document_tool` returns `status=skipped`** — Hash cache hit; the
  file content hasn't changed. Delete
  `$VIBE4FPGA_DATASHEET_DB_PATH/file_hashes.json` (or the default
  `~/.vibe4fpga/datasheet_qdrant/file_hashes.json`) to force a rebuild.
* **`qdrant_client` locking errors** — Qdrant local mode is single-process.
  Close any other tool (Jupyter kernel, separate IDE session) that may be
  holding the store open and retry. Remote Qdrant is out of scope for
  v0.2.0.
