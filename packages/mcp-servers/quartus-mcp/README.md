# quartus-mcp

MCP server that bridges Intel Quartus Prime (Pro & Lite) into Claude Code,
Codex CLI, and OpenCode over stdio.

## Overview

Wraps `quartus_sh --script` batch mode with nine MCP tools covering:

* **QSF management** — parse, generate, extend `.qsf` project files and
  manage pin assignments without touching the Quartus GUI.
* **Compilation flows** — full compile, A&S-only, TimeQuest timing report.
* **JTAG programming** — download `.sof` bitfiles via USB-Blaster.
* **Environment probe** — `quartus_environment` reports the resolved
  `quartus_sh` path and edition (**Pro / Lite / Standard**) so callers can
  detect a missing-vendor-tool upfront instead of debugging a cryptic
  compilation failure (plan §R4).

All subprocess invocations route through
[`vibe4fpga-platform`](../../shared/platform/) so UTF-8 codepages on Windows,
long-path prefixing, and deterministic timeouts are handled in one place.

## Install

Quartus Prime itself is a separate vendor install from Intel
(https://www.intel.com/content/www/us/en/software-kit/). The MCP server is
a thin Python wrapper around `quartus_sh`; installing it does **not**
install Quartus:

```bash
uv tool install quartus-mcp   # adds PATH entry "quartus-mcp"
```

Developers inside the monorepo use path-deps instead:

```bash
cd packages/mcp-servers/quartus-mcp
uv sync --all-extras
```

> Intel Quartus is Linux / Windows only. macOS is not a supported runtime
> target (CI matrix excludes `quartus-mcp × macos-latest`); tool-gated
> tests skip cleanly when `quartus_sh` is absent.

## Configure

### Claude Code — `%USERPROFILE%\.claude.json`

```json
{
  "mcpServers": {
    "quartus": {
      "command": "quartus-mcp",
      "env": { "QUARTUS_ROOTDIR": "C:\\intelFPGA_lite\\23.1\\quartus" }
    }
  }
}
```

### Codex CLI — `%USERPROFILE%\.codex\config.toml`

```toml
[mcp_servers.quartus]
command = "quartus-mcp"
env = { QUARTUS_ROOTDIR = "C:\\intelFPGA_lite\\23.1\\quartus" }
```

### OpenCode — `%APPDATA%\opencode\config.json`

```json
{ "mcp": { "quartus": { "type": "stdio", "command": ["quartus-mcp"] } } }
```

Host snippets are regenerated by `tools/gen-skills/generate.py` — never
hand-edit files under `configs/`.

## Tools

| Tool | Purpose |
| --- | --- |
| `read_qsf` | Parse a `.qsf` into structured project metadata |
| `create_qsf` | Emit a new `.qsf` with family / device / top / sources |
| `add_hdl_file` | Append a Verilog / SystemVerilog / VHDL source file |
| `assign_pin` | Set or update a pin + I/O-standard assignment |
| `compile_quartus_project` | Full compile: Analysis → Synthesis → Fit → Assemble → Timing |
| `synthesize_quartus` | Analysis & Synthesis only — fast error sanity check |
| `get_timing_report` | TimeQuest Fmax / WNS / per-clock slack summary |
| `program_fpga` | Download a `.sof` via USB-Blaster JTAG |
| `quartus_environment` | Report `quartus_sh` path + edition (Pro/Lite/Standard/Unknown) |

Every compilation-tool response carries the detected `edition` so callers
can specialize behavior (e.g. Pro-only IP cores, SDC dialect differences).

## Environment

| Var | Required? | Purpose |
| --- | --- | --- |
| `QUARTUS_SH` | optional | Absolute path to the `quartus_sh` executable — wins over PATH lookup. |
| `QUARTUS_ROOTDIR` | optional | Quartus install root; its `bin/` must be on PATH for vendor shell scripts to locate companions (`quartus_map`, `quartus_fit`, ...). |

Neither variable is strictly required — if `quartus_sh` is on `PATH` the MCP
resolves it via `shutil.which`. Missing Quartus produces a structured
`{"error": "quartus_sh_not_found", "hint": ...}` payload rather than a
stack trace.

## Windows notes

* **Vendor install.** Intel ships both the full **Quartus Prime Pro** and
  the free **Quartus Prime Lite** edition. `quartus_environment` runs
  `quartus_sh --version` and tags each compilation response with the
  detected edition (plan §R4). Pro-only features (partial reconfiguration,
  Hyperflex, certain SDC extensions) are silent no-ops on Lite — check the
  returned `edition` before relying on them.
* **Preferred env var.** Set `QUARTUS_SH=C:\intelFPGA_pro\23.4\quartus\bin64\quartus_sh.exe`
  directly — that bypasses the common `PATH` clutter from Model Sim and
  Platform Designer sub-tools that sometimes shadow the top-level binary.
* **Long paths.** `vibe4fpga-platform` transparently prefixes `\\?\` on any
  path exceeding 240 chars; enable `LongPathsEnabled=1` in Windows group
  policy for deep Quartus build directories regardless.
* **UTF-8 console.** `PYTHONIOENCODING=utf-8` + `PYTHONUTF8=1` are injected
  into the child env by `platform.proc.run`, which neutralises CN Windows
  GBK-console breakage when parsing Quartus logs.

## Troubleshooting

* **`{"error": "quartus_sh_not_found"}`** — install Quartus, then either
  add its `bin/` to PATH or set `QUARTUS_SH` to the absolute executable
  path. Call `quartus_environment` to confirm the fix.
* **`edition: "Unknown"`** — `quartus_sh --version` parse failed; usually
  harmless, but indicates a non-standard Quartus install. Report the raw
  version string by running `quartus_sh --version` manually.
* **`Quartus timed out after Ns`** — bump the `timeout` argument on the
  failing tool call. Defaults: compile 600 s, synth 300 s, timing 120 s,
  program 60 s.
* **Tests skip with "Quartus absent"** — expected on macOS / any box
  without Quartus installed. The `test_tool_gated.py` case only runs when
  `quartus_sh` resolves.
